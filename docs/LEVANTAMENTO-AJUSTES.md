- Revisar título, descrição, favicon e apresentação ao compartilhar links. Endereço canônico e URLs absolutas de compartilhamento dependem do domínio definitivo.
- Preparar a hospedagem para servir a pasta `Site` como raiz. Não é necessário transformar o projeto em aplicação com banco de dados para exibir o catálogo e encaminhar solicitações ao atendimento.

### Funcionalidades que hoje são apenas demonstrativas

| Área | Situação encontrada | Definição necessária |
|---|---|---|
| Contato | Prepara texto para copiar; não o envia ao ateliê | Destino real das solicitações |
| WhatsApp | Existe apenas um comentário para inserir o número; nenhum número configurado | Número oficial com DDD e país, se esse for o canal |
| Sacola | Guarda produtos e quantidades no navegador | Manter como seleção para orçamento ou integrar compra real |
| Frete | Retorna PAC R$ 18,90 / 5–8 dias e SEDEX R$ 31,40 / 2–4 dias para qualquer CEP com formato válido | Retirar a simulação e consultar no atendimento, ou definir serviço real |
| Pagamento | PIX e cartão são representações sem cobrança | Atendimento com pagamento combinado, ou checkout externo real |
| Finalização | Exibe sucesso e esvazia a sacola sem registrar ou transmitir pedido | Substituir por encaminhamento real, sem alegar pedido confirmado |
| Dados do checkout | Solicita nome, e-mail, telefone e endereço, mas não os envia | Simplificar conforme o fluxo comercial escolhido |

**Proposta para validação:** manter catálogo, filtros, detalhes e sacola; usar a sacola para montar uma solicitação com itens, quantidades e subtotal e encaminhá-la ao WhatsApp oficial. Frete, disponibilidade e pagamento seriam confirmados no atendimento. Os botões de eternização também abririam a conversa com contexto do interesse.

Esse fluxo atende à estrutura estática solicitada. Abrir o WhatsApp prepara uma mensagem para o visitante enviar; não comprova envio, pagamento ou recebimento do pedido. A interface precisa refletir isso. Caso o objetivo seja pagar diretamente no site, será preciso definir uma integração de pagamento/checkout; simplesmente remover os avisos de simulação não implementa compra real.

Depois de definido o fluxo, remover a lógica demonstrativa e revisar todos os textos relacionados, inclusive FAQ, avisos da sacola, frete, contato, limite de quantidade, `noscript` e tela de sucesso.
